# PLAN_V2 — визуал, прокачка, звук, скины

Решения владельца проекта от 11.10.2026. Этот файл дополняет `TASKS.md` и `MANUAL_TODO.md`.
Порядок разделов — порядок работ. Задачи `K*` делает исполнитель (код), `M*` — владелец (Unity, консоли, ассеты).

## 0. Уже применено в коде

- Офлайн-доход ограничен **4 часами** (`OfflineEarningsService.MaxOfflineSeconds = 14400`).
- Подарок LifetimeReward: **3 / 5 / 8%** от баланса, далее всегда 8%.
- Компенсация за досрочное закрытие рекламы: **3%** (было 5%).
- Владелец разрешил переделывать конфиги и переназначать ссылки в сцене.

## 1. Палитра (светлая воксельная)

Стиль: светлый, «игрушечный» воксель. Фон — небо, панели — почти белые, акцент — янтарный.
Тёмно-синий используется **только для текста**, не для фона. Никаких тёмных панелей.

| Роль | HEX | Где |
|---|---|---|
| Небо сверху | `#8FD3FF` | фон сцены, skybox верх |
| Небо снизу | `#E8F6FF` | skybox низ, градиент загрузки |
| Панель | `#FFFFFF` (alpha 240) | магазин, гараж, настройки, скины |
| Обводка панели | `#BFDCF0` | рамка 3–4 px |
| Акцент основной | `#FFB020` | главная кнопка, покупка |
| Акцент нажатый | `#E69500` | pressed state |
| Акцент второй | `#4FC3F7` | прогресс-бар, ссылки, иконки |
| Текст основной | `#12395C` | заголовки и значения |
| Текст вторичный | `#6E8CA8` | подписи, цена при нехватке |
| Положительное | `#58C873` | «доступно к покупке» |
| Отрицательное | `#FF7A6B` | не хватает денег, ошибка |
| Монета | `#FFCC33` / обводка `#E8A600` | иконка софт-валюты |
| Кристалл | `#8B6CF0` | донат-валюта |
| Прогресс: фон | `#DCEFFF` | дорожка полосы |
| Прогресс: заливка | `#4FC3F7` → `#8FE36B` | градиент слева направо |

Правило контраста: текст `#12395C` на белом и на `#FFB020` — читается. Серый текст на панели — только `#6E8CA8`, темнее не брать.

Скругления: панель 24 px, кнопка 16 px. Толщина обводки 3 px. Тени — мягкие, смещение вниз 4 px, прозрачность 18%.

### K2. HUD по макету

Файлы: `Scripts/UI/TopHudView.cs`, `Scripts/UI/BottomNavView.cs` (новый), Editor-скрипт из K1.

- Верх: слева баланс с иконкой монеты (`CurrencyBadge`), по центру «Машина N» + `ProgressBar` + «X / Y», справа доход «+N/сек».
- Низ: 4 кнопки-картинки — Гараж, Магазин, Скины, Настройки. Иконки берём из Kenney (M1). Подписи текстом не нужны, но добавить `Tooltip` в инспекторе.

Между ними `SafeArea` (учесть вырез экрана на телефонах): добавить компонент `SafeAreaFitter`, который в `OnEnable` подгоняет RectTransform под `Screen.safeArea`.
- Гараж и магазин — **отдельные окна поверх канваса**, каждое на весь экран, с собственным фоном. Пока окно открыто, HUD скрыт целиком (см. K3).

### K3. Гараж и магазин — отдельные окна

Файлы: `Scripts/UI/GarageView.cs`, `Scripts/UI/Shop/ShopView.cs`.

- В `GarageView` и `ShopView` добавить `[SerializeField] private GameObject[] _hideWhileOpen;` — сюда владелец кладёт HUD и кнопки нижнего меню.
- `Open()`: запомнить, какие объекты были активны, выключить их, показать окно.
- `Close()`: включить обратно только те, что были активны до открытия.

Приёмка: при открытом гараже на экране только гараж. Закрытие возвращает HUD в исходное состояние.

### K4. Прокачка: количество кубов и скорость спавна

Файлы: `Scripts/Gameplay/Systems/PartLifecycleService.cs`, `Scripts/Data/Configs/PhysicsConfig.cs`, `Scripts/Economy/Shop/UpgradeConfig.cs`, `Scripts/UI/Shop/UpgradeItemView.cs`.

**Проблема сейчас:** `RespawnDelay` — `private const float 2f` внутри `PartLifecycleService`, а `StartPartsPerWave` — просто поле конфига. Их нельзя улучшать.

1. В `PhysicsConfig` добавить:
   - `public float RespawnDelay = 2f;` (базовое значение)
   - `public int MaxPartsPerWave = 4;`
2. `PartLifecycleService` читает `_physics.RespawnDelay` вместо константы. Количество кубов берётся из `Mathf.Min(_physics.StartPartsPerWave + upgradeLevel, _physics.MaxPartsPerWave)`, где `upgradeLevel` — из `ShopModel` для ключа `spawn_count`.
3. В `UpgradeConfig` добавить поля, чтобы карточка показывала, **что** и **на сколько** растёт:
   - `public string StatNameKey;` — ключ локализации, например `stat.spawn_delay`
   - `public string UnitKey;` — `unit.sec` / `unit.count`
   - `public int Decimals = 2;` — сколько знаков
   - `public bool ValueDecreases;` — для задержки: значение уменьшается, это плюс
4. `UpgradeItemView` рендерит строку `было → станет` с единицей:
   - задержка: `2.00 → 1.95 с`
   - количество: `2 → 3 куба`
   Помечать стрелку зелёным, если покупка улучшает.
5. Два новых ассета-конфига (создать в редакторе, M3):
   - `Upgrade_RespawnDelay`: `BaseValue = 2.0`, `ValueStep = 0.05`, `ValueDecreases = true`, `BasePrice = 120`, `PriceMultiplier = 1.22`, `MaxLevel = 31` (2.00 → 0.50 с)
   - `Upgrade_SpawnCount`: `BaseValue = 2`, `ValueStep = 1`, `BasePrice = 25000`, `PriceMultiplier = 100`, `MaxLevel = 3` (2 → 3 → 4 куба, очень дорого)

Приёмка: в магазине две новые карточки, обе показывают было/станет с единицами. После покупки новые детали спавнятся быстрее, кубов становится больше.

### K5. Локализация: аргументы и данные конфигов

Файлы: `Scripts/Settings/Localizer.cs`, `Scripts/Settings/Localization.cs`, `Scripts/Economy/Shop/UpgradeConfig.cs`, `Scripts/Data/Configs/GarageCarData.cs`.

**Причина, почему не работало:** `Localizer` вызывал `Localization.Get(_key)` без аргументов, а ключи вида `Ур. {0}` требуют подстановки. Плюс название улучшения и описание машины — это данные конфига, их нельзя перевести ключом на TMP.

1. В `Localizer` добавить `[SerializeField] private string _formatArg;` — сюда можно вписать имя поля-числа, либо (проще) сделать отдельные компоненты `LocalizerLevel` и `LocalizerPrice` нет — вместо этого: `Localizer` получает публичный метод `SetArgs(params object[] args)` и не кэширует текст, а перерисовывается при вызове.
2. В `UpgradeConfig` добавить три поля имени и три поля описания: `NameRu/NameEn/NameTr`. Аналогично `GarageCarData`: `DescriptionRu/DescriptionEn/DescriptionTr`.
3. Добавить `Localization.Pick(string ru, string en, string tr)` — возвращает строку по текущему языку. Использовать в `UpgradeItemView` и `GaragePresenter`.
4. Удалить из таблицы ключи `shop.level/max/unlock` в формате `{0}` — заменить на вызовы с аргументами через `Localization.Get("shop.level", level)`.
5. Заполнить таблицу заголовками, которых не хватало: `hud.shop`, `hud.garage`, `hud.skins`, `hud.settings`, `gar.balance` (это баланс, а не доход — переименовать `hud.income` не нужно, но подписать под «+N/сек»), `settings.music`, `settings.sound`, `settings.language`.

Приёмка: `Ур. 5`, `Стадия 3`, `МАКС` корректны на ru/en/tr. Название улучшения и описание машины меняются при смене языка.

- Минимальные отступы: 24 px от краёв на 1080 ширины.

### K7. Звук

Файлы: `Scripts/Infrastructure/AudioService.cs` (новый), `Scripts/Infrastructure/Initializers/AudioInitializer.cs` (новый).

1. Два источника: музыка (loop) и SFX (PlayOneShot).
2. Громкость берётся из существующих полей `YG2.saves.musicVolume` и `YG2.saves.soundVolume`.
3. События: удар молота, раскол детали, покупка, разблокировка машины, клик кнопки, завершение стадии.
4. Музыка: отдельный трек для арены и для гаража, переключение в `Open/Close` гаража.
5. Все звуки подключаются через инспектор (`AudioClip` поля), код без хардкода путей.

Приёмка: ползунки в настройках меняют громкость, музыка меняется при входе в гараж.

### K8. Скины и донат-валюта

Файлы: `Scripts/Data/Configs/SkinConfig.cs`, `Scripts/Economy/SkinService.cs`, `Scripts/UI/SkinShopView.cs` (все новые).

1. `SkinConfig` (ScriptableObject): `Id`, `Type` (Hammer / Bowl / Background), `DisplayNameRu/En/Tr`, `Price`, `Currency` (Soft / Hard), `Preview`.
2. `SkinService`: список скинов, купленные в `YG2.saves` (новый `List<string> ownedSkins`), текущий выбранный по типу.
3. `SkinShopView`: сетка карточек, две вкладки — «за монеты» и «за кристаллы».
4. **Важно:** донат-валюта в Яндекс.Играх — это XTR API. Пока консоль не настроена, вкладка «за кристаллы» скрывается флагом `_hardCurrencyEnabled = false`. Это делает владелец (M6).

Приёмка: скин за монеты покупается, применяется, сохраняется после перезапуска.

### K9. Частицы

Файлы: `Scripts/UI/ProgressBarShine.cs` (новый), префабы эффектов создаёт владелец (M4).

1. Удар: вспышка искр в точке удара — вызов из `CarPart.TakeDamage`.
2. Раскол: короткий «поп» из частиц цвета детали — вызов из `CarPart.Die`.
3. Прогресс-бар: бегущий блик по заливке при каждом изменении прогресса.
4. Разблокировка машины: конфетти в окне гаража.
5. Код только вызывает `ParticleSystem.Play()`. Сами эффекты — префабы в `Assets/Prefabs/FX/`.

Приёмка: удар даёт искры, раскол — вспышку, новая машина — конфетти.

### K10. Экран загрузки: цветной водопад

Файл: `Scripts/Core/BootScreen.cs`.

**Почему сейчас «стая комаров»:** кубы спавнятся в плоскости перед камерой и не красятся — `ColorChanger` живёт на `CarPart`, а `BootScreen` инстансит куб напрямую.

1. Спавн в объёме: `x` в пределах ±ширины, `y` от верха области, `z` от 2 до 8 перед камерой.
2. Каждому кубу — случайный цвет из палитры (HSV, насыщенность 0.8–1.0, яркость 0.85–1.0), случайный размер 0.6–1.4 и случайное вращение.
3. Падение мимо объектива: `z` не меняется, `y` уменьшается, при выходе за низ — возврат наверх со сдвигом `x`.
4. Фон: градиент `#8FD3FF` → `#E8F6FF` (обычный `Image` на Canvas позади кубов).
5. Материал куба — unlit, чтобы не зависеть от освещения.

Приёмка: на загрузке падают разноцветные кубы разного размера, фон светлый градиент.
